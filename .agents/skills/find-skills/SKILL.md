# 查找 Skill

你负责帮助用户发现适合当前任务的 Skill。目标不是盲目增加 Skill，而是先确认现有能力能否满足需求，再推荐最小、最匹配的方案。

## 触发场景

- 用户说“有没有做某事的 Skill”“帮我找一个 Skill”。
- 用户询问某个能力是否可以扩展，或希望增加专门的工作流。
- 用户想搜索、比较、迁移或安装外部 Skill。
- 用户描述了一个复杂领域任务，而已有 Skill 可能提供稳定方法。

## 工作流程

### 1. 理解需求

提取领域、具体任务、需要的是规则/流程/工具/模板，以及项目边界、平台限制、授权和数据安全要求。

### 2. 先查本地

优先检查：

- 当前项目的 `.agents/skill/`。
- 项目正式 Skill 目录 `.agents/skills/`。
- 用户明确提供的本地路径或仓库。
- 当前会话已经可用的 Skill 与工具。

使用 `rg --files`、`find` 或等价的只读方式搜索名称、描述和触发条件。发现已有能力时，直接说明适用范围，不要为了换一个名字重复创建。

### 3. 判断外部候选

只有本地能力不足时才考虑外部来源。比较候选的能力覆盖、宿主依赖、项目适配成本、重复内容、维护负担和授权风险。不能把未知来源内容直接写入项目。

### 4. 输出建议

先给结论，再说明：Skill 名称和用途、能解决与不能解决的问题、现有本地路径、安装前提和来源。没有合适候选时，明确说明没有找到，并建议直接完成任务或创建项目内部 Skill。

## 安装与迁移边界

- 用户只要求查找时，不执行安装、复制或修改。
- 用户明确要求安装时，使用当前可用的 Skill 安装能力或项目约定的导入流程，不假设存在某个外部 CLI。
- 用户明确要求迁移时，先提炼能力，再改写成英文 Skill 标识、中文正文和本项目路径。
- 不复制完整上游仓库，不保留 `_upstream`、`source-copy`、`legacy` 或备用提示词。
- 推荐结果必须与当前任务相关，避免堆砌热门但无关的 Skill。

## 终检

- 是否先查过本地 Skill。
- 是否区分了查找、推荐、安装和迁移。
- 是否说明依赖、边界和授权风险。
- 是否避免承诺当前不可用的工具、命令或外部服务。
- 用户可见说明、示例和建议是否为中文。
